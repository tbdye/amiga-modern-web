# Prior art: Amiga clients of an engine elsewhere, part by part

Scope: the existing Amiga programs that show pages or a desktop rendered on another computer (AmiFox, TwinVNC, amifleet68, a 68k Remote Desktop client), with the Web Rendering Proxy's VNC mode as a server for them: what each has and lacks part by part, their licences with each of TwinVNC's notices, and the Remote Desktop client's 2005 source as read.
Status: current

- What each project is, what crosses the wire, and how each draws received pixels and moves a scroll: `topics/prior-art.md`, "Remote and split-engine browsers"; those rows are not repeated here.
- Nothing here was built or run: `[F]` is what a source at its pin contains or says, and "none" is a search of that project's own source files at the pin, for the words given where the search is not plain from the cell.
- VNC's protocol is RFB; MUI and GadTools are Amiga interface toolkits; DataTypes are AmigaOS's decoders by file type; AHI is the Amiga's audio system; ASL supplies its file requesters.
- A citation without a repository is in the repository and commit last named in its cell, or named in the heading row of its table; every source ID here is defined in `sources.md`, "Prior-art sources".

## The 68k Remote Desktop client's 2005 source

- [F] The port's site, as archived on 2007-02-10, announces a 68k build for AmigaOS 3.x on 2005-03-02 and links a source archive of 2005-02-05; it lists audio forwarding that "requires AHI", "Clipboard support", "8/16/24-bit true colour support" and "functions of Picasso 96 or CyberGraphX for accelerated graphics", and recommends "a 68060 cpu and a graphics card" (`rd-pages`).
- [F] Its change log names later 68k versions: one of 2006 on rdesktop 1.4.1, and one made available on 2007-03-29 (`rd-pages`).
- [F] Searches of Aminet and OS4Depot for "rdesktop" on 2026-10-11 returned PowerPC builds only (`rd-pages`).
- The archive, `rd68k`, was read as text; paths below are in its top directory, and `base/` stands for its directory `rdesktop-2004-04-17-0600/`.

| What | What the source shows |
|---|---|
| Licence | [F] Each Amiga file: the GNU General Public License, "either version 2 of the License, or (at your option) any later version"; `COPYING`: that licence with an exemption allowing OpenSSL to be linked (`rd68k:amiga.c:L7-10`; `COPYING:L1-4`) |
| rdesktop base | [F] Version 1.3.1, from an upstream snapshot of 2004-04-17; the program names itself "RDesktop 1.3.1cvs-AmigaOS (29.01.2005)" (`rd68k:base/Makefile:L15`; `ChangeLog:L202`; `amiga_rdesktop.c:L103-109`) |
| 68k target and libraries | [F] Host `m68k-unknown-amigaos`, `CPU="68020"`, libnix or `ixemul` V48; it opens `graphics.library`, `intuition.library` and `layers.library` at version 39, and `cybergraphics.library` 40 without requiring it (`rd68k:configure.ac:L6-23`; `amiga_rdesktop.c:L414, L450, L539, L574-587`) |
| Cryptography | [F] This build takes it from an OpenSSL library outside the archive (`-DWITH_OPENSSL`, with a link check for `-lcrypto`); the base also carries RC4, MD5, SHA-1 and big-number code of its own in `base/crypto/`, for builds without that library (`rd68k:Makefile.in:L8`; `configure.ac:L63`; `base/secure.c:L23-40`; `base/crypto/README`) |
| Window and pointer | [F] On a public screen, an Intuition window with drag bar, depth and close gadgets and a zoom box, with no sizing gadget, by default 80% of the screen; or a screen of its own; the session's depth follows the screen's: 8, 15, 16, and 24 for 24- and 32-bit screens; the server's pointer shape becomes an Intuition pointer on the window (`rd68k:amiga.c:L1298-1312, L1336-1360, L1481-1550, L2250-2385`) |
| Bitmaps | [F] At 8 bits pens are remapped and written with `WritePixelArray8`; at 15, 16 and 24 bits as `topics/prior-art.md` states; `Picasso96API.library` is opened only to learn whether it is present (`rd68k:amiga.c:L238-287, L628-631, L1369-1381`) |
| Drawing orders | [F] It lists to the server destination, pattern, screen and memory blits, line, rectangle, desktop save, three-way blit, polyline and text; it draws them with `ClipBlit` or `BltBitMapRastPort`, `RectFill`, `Move` and `Draw`, and `BltTemplate`, and patterns one `WritePixel` at a time; where Picasso96 is absent and the screen is deeper than 8 bits, raster operations other than copy are done in RAM between `ReadPixelArray` and `WritePixelArray` (`rd68k:base/rdp.c:L428-456`; `amiga.c:L395-615, L1369-1376, L2620-2851`) |
| Its switch for bitmaps only | [F] `BITMAPSONLY` clears a flag that no file in the archive reads where the list of orders is filled; [G] so in this source the switch does not change the list (`rd68k:amiga_rdesktop.c:L859`; `base/rdp.c:L433-447`) |
| Sound | [F] `ahi.device` version 4 on the chosen unit; PCM only, 8 or 16 bits, one or two channels; 16-bit samples are byte-swapped in place on a big-endian machine; blocks wait in a queue of 10; a block is confirmed to the server when it is handed to AHI, not when it has played (`rd68k:rdpsnd_ahi.c:L32, L79-81, L153-166, L191-192, L307-338`) |
| Clipboard | [F] Plain text only, both ways, through the clipboard's IFF text form; other formats are ignored (`rd68k:amiga_clipboard.c:L37-38, L103, L197-269`; `ChangeLog:L94-96`) |
| Keys | [F] Amiga raw key codes are mapped to PC scancodes in one table; the Windows keyboard layout is chosen from the Amiga's country (`rd68k:amiga.c:L835-1169`; `ChangeLog:L3-5`) |
| Left out of this build | [F] Drives, printing and serial and parallel ports: their objects are commented out of the build, and every redirected-device request ends in "IRP for bad device"; no resize; moving the pointer from the server is an empty function (`rd68k:Makefile.in:L21-26`; `base/rdpdr.c:L369-397`; `amiga.c:L2116-2120`) |

## Not established

- Whether any program on this page works as its documentation says, and its rate on any Amiga: nothing was run, and no published figure was found for TwinVNC or the Remote Desktop client; only running a program shows it.
- Whether TwinVNC and the proxy's VNC mode work together: reading shows what each sends and accepts, not that the pair works.
- Which of TwinVNC's notices applies to its source directory, and the terms of its socket files: the repository does not say, and only a statement in it would settle either.
- Whether TwinVNC builds with a 68k GCC: its only 68k build files are for SAS/C, and a build would settle it.
- Whether the 2005 archive is complete and builds: the OpenSSL library its build asks for is not in it, and a build would settle it.
- Whether the archived 68k binary of the Remote Desktop client is intact, and whether source for its 2006 and 2007 versions survives: neither was fetched or found.
- Whether that client works against an RDP server of today, and at what rate: not established by reading.
- The licence terms of the Free Pascal run-time and of MUI for redistribution, and of AmiFox's session distributor: not read.
